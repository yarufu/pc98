## 左右ステータス表示

通常フラグ`status_ui`がONの間、左下パネルへ日付と曜日、右下パネルへ
時刻と所持金をそれぞれ2行で表示します。日付は`month`と`day`を2桁
ゼロ埋めした`MM/DD`、時刻は`hour`と`minute`を2桁ゼロ埋めした
`HH:MM`、所持金は`money`を5文字幅で右詰めします。

曜日は`weekday`の0～6を日曜日～土曜日として表示します。範囲外なら曜日欄は
空欄になります。`month`は1～12、`day`は1～31をスクリプト側で設定し、
月末判定や曜日計算は行いません。各値は既存の数値変数としてセーブされます。

`money`は16bit数値変数のため、スクリプト側で0～32767の範囲に収めます。
日付、曜日、時刻、所持金には固定ファイル`STATUS.SPR`を共用します。画像は160×32、
1文字16×16で、上段（y=0～15）に数字0～9、下段（y=16～31）に
日・月・火・水・木・金・土・曜・／・：を配置します。ステータス更新1回につき
1回だけ読み込んですべてを描画します。
`STATUS.SPR`はステータス画像表示に必要です。ファイルが存在しない、または読み込みに
失敗した場合はステータス欄を空欄のままとしてゲームを継続し、CG-ROMによる代替表示は
行いません。時計と日付の自動進行はありません。

```text
#setnum month 11
#setnum day 19
#setnum weekday 0
#setnum hour 11
#setnum minute 30
#setnum money 5000
#set status_ui

#add money -300
#reset status_ui
```

`weekday`は0=日、1=月、2=火、3=水、4=木、5=金、6=土です。
`#set status_ui`で左右の表示を開始し、`#reset status_ui`で終了します。
`#set status_ui`で直ちに初回表示し、一度表示した後の数値変更も従来どおり即時反映されます。

## FM効果音仕様

ADV98.EXE では、PMD の FM効果音機能を使用します。

FM効果音データは、実行ファイルと同じフォルダに配置した `SE.EFC` から読み込みます。

`#se <番号>` で0～127のFM効果音を再生します。引数が範囲外、数値以外、
または `SE.EFC` が読み込まれていない場合は、何もせずゲームを続行します。

```
#se 2
```

効果音番号 1 はシステム効果音として使用されています。

## UIテーマ

通常ゲーム画面の初期UIは640×400の`UI.G98`です。次の命令で、現在のUIを
別の640×400 G98へ即時変更できます。

```text
#ui UI2.G98
#ui PROLOG.G98
#ui UI.G98
```

UIファイル名は拡張子を含むDOS 8.3形式、最大12文字とし、空白やディレクトリは指定しません。
13文字以上、引数なし、追加引数、`none`は不正指定として無視します。`#ui none`による
UI非表示には対応していません。

UI分離モードで変更に成功すると、現在の背景のX=60～579、Y=0～298、左右立ち絵、
ステータスを通常描画で復元します。全画面CGモード中は`ui_file`の記録だけを変更し、
表示中の全画面CG、立ち絵、ステータス、画面モードを変更しません。記録したUIは、次の
`#bg`または`#bginterlace`でUI分離モードへ戻るときに使用します。

現在の16色パレットとBGMは変更しません。メッセージ本文と選択肢は保持しないため、
UI分離モードで即時反映する`#ui`はメッセージ間で使用します。読込失敗時は現在の画面と
UI名を維持します。

現在のUI名はversion 6セーブへ保存されます。version 4データのロードでは`UI.G98`を使用し、
version 4／5データの画面モードはUI分離モードとして扱います。
保存されたUIをロードできない場合は`UI.G98`へフォールバックし、成功時は状態名も
`UI.G98`へ更新します。UI専用パレットはなく、必要なら`#ui`の前に`#pal`を指定します。

## 全画面CG表示

ADV98は、UI分離用の`SCENE_MODE_SEPARATED_UI`と、640×400全体を1枚のG98として扱う
`SCENE_MODE_FULLSCREEN_CG`を区別します。初期状態と新規ゲームはUI分離モードです。
両モードとも現在画像名は`background_file`（実装上は`GameState.bg_file`）へ保存し、
別のCGファイル名フィールドは持ちません。

```text
#cg CUSTOM.G98
#cginterlace EVENT.G98
```

`#cg`は640×400 G98を画面全体へ通常表示し、全画面CGモードへ移行します。`#ui`の画像は
重ねません。現在の左右立ち絵をその後に通常合成し、`status_ui`がONなら固定座標へ
ステータスを再描画します。選択中の`ui_file`は消去しません。

`#cginterlace`の最終状態は`#cg`と同じです。ページ1へ完成G98を読み終えてから、表示ページ0を
維持してX=0～639、Y=0～399を8ライン単位・50段階で転送します。上側の偶数ラインと
下側の奇数ラインを各段階最大4本ずつ処理し、400ラインを重複・欠落なく1回ずつ描画します。
演出中のファイルI/Oと終了後の全画面再転送はありません。演出完了後に立ち絵とステータスを
重ねます。

どちらの命令もパレットを変更しません。必要な場合は先に`#pal`を指定します。命令は完全一致で
解析するため、`#cginterlace`が`#cg`として扱われることはありません。引数はDOS 8.3形式の
G98名1個だけです。引数なし、追加引数、`none`、13文字以上は無視します。G98が存在しない、
ヘッダ不正、640×400・4プレーンBRGI以外、または読込み失敗の場合は、表示中のシーン、
`bg_file`、画面モードを従来状態へ戻します。

純粋な一枚絵にする場合は、立ち絵とステータスをスクリプト側で明示的に解除します。

```text
#left none
#right none
#reset status_ui
#pal EVENT.PAL
#cginterlace EVENT.G98
```

## 背景表示

通常ゲーム画面では、初期`UI.G98`または`#ui`で選択したUIが自動的に使用されます。
背景表示領域はX=60～579、Y=0～298（520×299）です。中央上部の横線は固定UI要素とせず、
背景をY=0から連続して表示します。左右のX=0～59／580～639と下部のY=299～399は
従来どおりUI領域です。
使用するUIファイルは実行ファイルと同じフォルダへ配置します。

背景命令は、拡張子を含むG98ファイル名を直接指定します。
ファイル名はMS-DOSの8.3形式（ベース名8文字以内、拡張子3文字以内）とし、
ディレクトリや空白は使用しません。エンジンは`.G98`を自動付加しません。
背景ファイルは従来どおり640×400形式とし、ゲーム画面矩形だけが表示へ反映されます。

`#bg <G98ファイル名>`は通常表示です。表示中のページ0を維持したまま、ページ1へ
背景のゲーム画面矩形、現在の左立ち絵、現在の右立ち絵の順で完成シーンを作ります。
既存8KBバッファを経由してX=60～579、Y=0～298だけをページ0へ転送し、
表示・CPUアクセスページを0にそろえます。固定UI領域は変更しません。

`#bginterlace <G98ファイル名>`は背景表示矩形だけを38段階でインターレース表示します。
矩形上側は相対偶数ラインを上から下へ、下側は相対奇数ラインを下から上へ、
1ラインおきに段階的に表示されます。Y=0～298の299ラインは重複・欠落なく1回ずつ転送され、
固定UI領域は演出中も変化しません。背景名には通常の640×400 G98を指定します。

```
#bg CLASS.G98
#bginterlace CLASS.G98
```

`#bg`と`#bginterlace`は実行成功後にUI分離モードへ切り替わります。直前が全画面CGモードなら、
保持中の`ui_file`を640×400全体へ復元してから背景矩形を通常表示またはインターレース表示し、
左右立ち絵、`status_ui`の順に復元します。すでにUI分離モードなら、UI外周を再読込みせず
従来の背景矩形更新を継続します。

通常`#bg`の完成シーン準備に失敗した場合はページ0へ戻し、直前の画面モード、背景名、表示を
復元します。これにより全画面CGからの復帰失敗時にUIだけが重なった状態を残しません。
背景が未指定の新規状態ではゲーム画面矩形を黒くして`BG LOAD NG`を表示します。
SPR読み込み失敗時は`SPRITE LOAD NG`を表示してゲームを続行します。

`#bginterlace`の演出後は、GameStateに保存されている現在の左右立ち絵を再描画します。
セーブ時は通常背景と同じくG98ファイル名だけを保存します。
ロード時は通常`#bg`と同じ裏画面完成合成方式で復元され、インターレース演出は再実行されません。

## 立ち絵インターレース表示

立ち絵命令は、拡張子を含むSPRファイル名を直接指定します。
ファイル名はMS-DOSの8.3形式（ベース名8文字以内、拡張子3文字以内）とし、
ディレクトリは指定しません。エンジンは`.SPR`を自動付加しません。

通常の`#left <SPRファイル名|none>`と`#right <SPRファイル名|none>`で
立ち絵だけを部分更新する場合は、表示中のページ0を維持したまま、ページ1へ対象領域の
背景を読み込みます。SPR指定時はその上へ透明合成して完成矩形を作り、既存8KBバッファを
経由してページ0へ8ライン単位で転送します。各単位の書き込み順はB/R/G/Iです。

通常命令へ`none`を指定した場合は、ページ1へ背景だけの完成矩形を作り、同じ8ライン転送で
旧立ち絵を即時消去します。8ラインという転送単位は内部実装で固定されており、スクリプトから
指定または変更できません。

背景変更とロード復帰では、ページ1へ背景＋左右SPRの完成シーンを作ってからゲーム画面矩形だけを
ページ0へ転送します。部分更新用の転送は再実行せず、背景矩形の再読み込みも行いません。

`#leftinterlace <SPRファイル名|none>` と
`#rightinterlace <SPRファイル名|none>` は、裏画面VRAMへ対象領域の背景を読み込み、
SPR指定時はその上へ透明合成した完成矩形を作ってから、ページ0へ走査線状に表示します。
表示ページはページ0のまま維持され、演出中はページ1からRAMを経由するVRAM転送だけを行います。

`none`を指定すると、裏画面には背景だけの完成矩形を作ります。その背景を同じ順序で
転送するため、表画面の旧立ち絵は一瞬で消えず、インターレース状に段階消去されます。
引数なしの命令は、状態と画面を変更せず無視します。背景またはSPRの準備に失敗した場合も
表画面は変更せず、表示ページとCPUアクセスページをページ0へ戻します。

通常`#bg`と立ち絵インターレース命令を同じメッセージ表示前に指定した場合、演出予定側は
背景完成シーンへ通常合成せず、背景切り替え後に正式インターレース処理を実行します。
左右両方が演出予定なら左、右の順です。通常側の立ち絵は背景完成シーンへ含まれます。

```
#left C01_N.SPR
#right C02_H.SPR
#leftinterlace MIO_UNI.SPR
#rightinterlace MIO_EV1.SPR
#left none
#right none
#leftinterlace none
#rightinterlace none
```

通常命令の`none`は即時消去し、インターレース命令の`none`は段階消去します。
従来のキャラクター番号と表情名の引数は廃止しました。
制服・私服・イベント専用画像などを、任意の8.3形式SPR名で指定できます。

GameStateには従来どおりSPRファイル名だけを保存します。ロード復帰とメニュー後の再描画では、
完成画面を通常描画し、インターレース演出は再実行しません。

立ち絵座標は両モードとも左X=64、右X=320、Y=9、サイズ256×290です。通常更新と
インターレースのいずれも、古い立ち絵の下地には現在の`bg_file`の同じ矩形を使います。
全画面CGモードでは左右端・下部を含む全画面CGが再描画元となり、UI画像は重ねません。
