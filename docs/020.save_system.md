# ADV98 セーブシステム仕様

## 概要

ADV98 ではゲームの進行状況をセーブファイルへ保存できます。

セーブデータは 3 スロット対応です。

```txt
SAVE1.DAT
SAVE2.DAT
SAVE3.DAT
```

セーブおよびロードはシステムメニューから行います。

---

## セーブ対象

セーブ時には以下の情報を保存します。

* 現在のスクリプト位置
* 現在の背景
* 現在のUIファイル名
* 現在の画面モード
* 左右のSPRファイル名
* 現在のBGM
* 通常フラグ
* 数値フラグ

ロード時にはこれらの状態を復元し、保存位置からゲームを再開します。

---

## セーブファイル形式

### SaveDataV6

```c
typedef struct {
    char magic[8];
    int version;

    GameState state;
    GameFlag flags[MAX_FLAGS];
} SaveDataV6;
```

IA16ビルドでのサイズは692Bです。

---

### magic

セーブデータ識別子です。

```txt
ADV98SAV
```

セーブファイルが ADV98 用であることを判定します。

---

### version

セーブデータ形式のバージョン番号です。

現在の保存形式はversion 6です。version 6は選択中のUIファイル名に加えて画面モードを保存します。
version 4と5は旧レイアウト専用構造体で互換読込し、version 3以前と未知のversionは拒否します。

---

## GameState

ゲームの進行状態を保存します。

```c
typedef struct {
    char bg_file[BG_FILENAME_SIZE];
    int script_line;
    int call_stack[CALL_STACK_MAX];
    int call_stack_depth;

    char left_sprite[SPRITE_FILENAME_SIZE];
    char right_sprite[SPRITE_FILENAME_SIZE];

    char bgm[64];
    char ui_file[UI_FILENAME_SIZE];
    uint8_t scene_mode;
} GameState;
```

IA16ビルドでのサイズはversion 4が124B、version 5と現在のversion 6が138Bです。
`scene_mode`はversion 5構造体末尾にあった1Bのアライン余白（offset 137）を再利用するため、
`GameState`とセーブ1スロットのサイズは増えません。

---

### bg_file

現在表示中の8.3形式のG98ファイル名です。拡張子`.G98`を含めて保存します。
UI分離モードではX=60～579、Y=0～298を使い、全画面CGモードでは640×400全体を使います。
空文字列は背景ファイル名なしを表します。

例：

```txt
SCHOOL.G98
CLASS.G98
GYM.G98
```

---

### script_line

現在実行中のスクリプト行番号です。

ロード時はこの位置から再開します。

---

### ui_file

現在選択中のUIを、拡張子込みのDOS 8.3形式で保存します。全画面CGモードでは表示へ
重ねませんが、後でUI分離モードへ戻すため保持します。配列長は13Bで、
最大12文字と終端NULです。新規ゲームとversion 4からの移行では`UI.G98`を設定します。
空文字のversion 5状態も`UI.G98`へ補正しますが、配列内にNULがないversion 5データは
破損データとしてロードを拒否します。

---

### scene_mode

`SCENE_MODE_SEPARATED_UI`（0）または`SCENE_MODE_FULLSCREEN_CG`（1）を`uint8_t`で保存します。
version 4／5にはこのフィールドがないため、ロード時はUI分離モードを補います。
version 6で範囲外の値は破損データとして拒否します。

---

### left_sprite / right_sprite

左右に表示する8.3形式のSPRファイル名です。拡張子`.SPR`を含めて保存します。
空文字列は立ち絵なしを表します。

---

### bgm

現在再生中のBGMファイル名です。

例：

```txt
opening.m
school.m
```

ロード後は自動的に再生を再開します。

---

## GameFlag

ゲーム内フラグを保存します。

```c
typedef struct {
    char name[32];
    int value;
} GameFlag;
```

通常フラグと数値フラグを共通形式で管理します。

例：

```txt
route_a = 1
money = 1000
love = 50
```

---

## ロード処理

ロード成功時は以下を実行します。

1. magicとversionを確認
2. versionに応じてGameStateとGameFlagを復元
3. 保存時点のパレットを復元
4. 画面モードに従って最終シーンを演出なしで復元
5. ステータスを再描画
6. BGMを再開
7. 保存位置からスクリプトを再開

UI分離モードでは、`ui_file`全体、`bg_file`のX=60～579／Y=0～298、左右立ち絵、
ステータスの順です。全画面CGモードでは、`bg_file`の640×400全体、左右立ち絵、
ステータスの順で、`ui_file`は表示しません。タイトルからのロードでも同じ再構築関数を使うため、
タイトル画像やUI画像は残りません。`#bginterlace`と`#cginterlace`の演出は再生しません。

version 5の保存UIが見つからない場合は`UI.G98`へフォールバックします。成功時は
表示内容と次回セーブを一致させるため、`ui_file`も`UI.G98`へ更新します。
フォールバックも失敗した場合はUI領域を黒くしてゲームを続行します。

### version 4／5互換読込

version 4のレイアウトは次の専用構造体で再現します。

```c
typedef struct {
    char bg_file[BG_FILENAME_SIZE];
    int script_line;
    int call_stack[CALL_STACK_MAX];
    int call_stack_depth;
    char left_sprite[SPRITE_FILENAME_SIZE];
    char right_sprite[SPRITE_FILENAME_SIZE];
    char bgm[64];
} GameStateV4;

typedef struct {
    char magic[8];
    int version;
    GameStateV4 state;
    GameFlag flags[MAX_FLAGS];
} SaveDataV4;
```

`SaveDataV4`は678Bです。背景、スクリプト位置、CALLスタック、左右SPR、BGMを
現行`GameState`へ項目単位で移行し、UI名を`UI.G98`に設定します。V4をロードした後の
新しいセーブはversion 6になります。サイズの異なる構造体キャストや一括コピーは使用しません。

version 5は上記に`ui_file[13]`を加えた138Bの`GameStateV5`と、692Bの`SaveDataV5`で
再現します。背景、進行位置、CALLスタック、左右SPR、BGM、UI名を移行し、画面モードだけを
`SCENE_MODE_SEPARATED_UI`へ設定します。

ロード関数は692BのV4/V5/V6 unionを1個だけローカルに確保します。先頭10Bのmagicとversionを
確認後、ファイル先頭へ戻って対応する構造体サイズだけを読み込みます。

---

## エラー処理

以下の場合はロードに失敗します。

* セーブファイルが存在しない
* セーブファイルを開けない
* magic が一致しない
* version が3以前または7以降
* 読み込みサイズが不正
* version 5のファイル名配列にNUL終端がない
* version 6のファイル名配列にNUL終端がない、または画面モードが範囲外

ロード失敗時はゲーム状態を変更しません。

---

## 備考

セーブデータ形式を変更した場合はversionを更新してください。現在はversion 4と5を
明示的に互換読込します。既存の`SAVE1.DAT`～`SAVE3.DAT`をロードしてもファイル自体は
書き換えず、次に保存した時点でversion 6になります。
